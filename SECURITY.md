# Security policy

This code sits in the execution path of privileged actions. We would much rather hear about a
weakness from you than from an incident, and we will not argue about whether it counts.

## Reporting

**Do not open a public issue for a security report.**

Use GitHub's [private vulnerability reporting](https://github.com/Metamynd/agentsafe-guard/security/advisories/new)
on this repository, or email **security@metamynd.ai**.

Please include what you have: the version, what you did, what happened, and what you expected.
A rough report you are unsure about is more useful to us than a polished one you never send.

## What to expect

| | |
|---|---|
| Acknowledgement | within **3 working days** |
| Initial assessment | within **10 working days** |
| Fix or a dated plan | agreed with you, based on severity |
| Credit | offered by default; tell us if you would rather not be named |

We will keep you updated while it is open rather than going quiet, and we will tell you plainly
if we assess something as not exploitable and why — so you can push back.

## Scope

**In scope** — anything in this repository, and the protocol behaviour it implements:

- Verdict correctness: an action that should have been refused being permitted
- Signature, nonce or replay handling in the guard
- Anything that lets an agent evaluate as *more* authorised than its mandate allows
- Fail-open behaviour where the guard should fail closed
- Local policy-bundle handling: staleness, signature verification, rollback

**Also of interest, though hosted rather than here** — the authorize gate at `metamynd.ai`.
Report those the same way. Please do not run automated scanning, load testing, or anything
disruptive against the production gate; if you need a target, the
[public sandbox](https://metamynd.ai/developers/sandbox) exists and needs no account.

**Out of scope**

- Findings that require an attacker to already control the agent's private key or its host
- Denial of service through sheer request volume against the hosted gate
- Missing hardening headers on the marketing site
- Reports generated by a scanner with no analysis of whether the finding is reachable

## Design decisions that are intentional

Some of these look like findings on first contact, so it is worth stating them:

- **The guard fails closed.** An unreachable gate blocks rather than allows. Availability of
  the gate is therefore a dependency for value-bearing actions. This is a deliberate trade and
  it is documented in the README.
- **Blocks and escalates are decided locally**, in-process, against a signed policy bundle.
  Bundle signature and staleness are enforced, and a value-bearing action is fail-closed if the
  bundle cannot be proven current.
- **The evaluator is fully published, on purpose.** Verdict reproducibility is a stated property
  of the protocol ([MAGP §6.3](https://metamynd.ai/developers/spec)), not an oversight.
  Knowing the rules is not the same as being able to change them: authority is issued and
  anchored server-side.

## Supported versions

The latest published minor of each package. We do not backport to earlier lines; if that is a
problem for you, say so in the report and we will discuss it.
